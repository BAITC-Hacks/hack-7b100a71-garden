# Career Quest backend

Backend для команды HackAlem AI: профили сотрудников, каталог мероприятий, история участия, завершение активности, импорт данных жюри и агрегированная HR-аналитика. FastAPI, Pydantic и PostgreSQL в Supabase. Исходный датасет загружается из JSON/CSV. Для локального демо доступно файловое хранение.

Работа Bekarys находится в `backend/`. Подбор карьерной цели, ранжирование, readiness и AI-объяснения подключаются из движка Zhanibek через [контракт интеграции](docs/INTEGRATION.md). Контракт для frontend Adilet описан в [API.md](docs/API.md).

## Подключение Supabase

В Supabase откройте **Connect → Session pooler** и добавьте PostgreSQL URL в локальный `.env` как `DATABASE_URL`. Используйте адрес из своего проекта, пароль базы и `?sslmode=require`; специальные символы пароля нужно URL-кодировать. Пример переменной есть в `.env.example`.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m backend.db init
./run.sh
```

`init` применяет SQL-миграции и загружает данные только в пустую базу. Если есть `.runtime/state.json`, его прогресс и сохранённые ответы также переносятся; исходный файл остаётся на месте. Повторный `init` сохраняет действующие данные. Для проверки подключения и количества записей:

```bash
.venv/bin/python -m backend.db status
```

При заданном `DATABASE_URL` API использует Supabase. Ошибка подключения возвращает ошибку, без переключения на локальные данные. Схема, таблицы, транзакции и настройка доступа описаны в [SUPABASE.md](docs/SUPABASE.md).

## Запуск одной командой

Из корня репозитория:

```bash
CAREER_QUEST_AUTH_DISABLED=true ./run.sh
```

Скрипт создаёт `.venv`, устанавливает зависимости и запускает сервер на `http://127.0.0.1:8000`. Рекомендуется Python 3.11 или новее. [Swagger UI](http://127.0.0.1:8000/docs) позволяет отправлять запросы; [health](http://127.0.0.1:8000/health) показывает загруженный набор данных.

В этой команде явно включён локальный деморежим: все запросы получают права HR. Он предназначен для синтетического датасета. Для проверки разграничения доступа создайте `.env` по образцу `.env.example`, отключите деморежим и задайте собственные токены:

```dotenv
CAREER_QUEST_AUTH_DISABLED=false
HR_API_TOKEN=your-own-hr-token
EMPLOYEE_TOKENS_JSON={"your-own-employee-token":"E0001"}
```

Затем запустите `./run.sh`. Запросы используют `Authorization: Bearer <token>`. Сотрудник получает только свой профиль и историю; HR — список сотрудников, аналитику и импорт. Без настройки токенов защищённые маршруты недоступны. Простой адаптер токенов предназначен для хакатона; полноценная система входа не включена.

## Основные API

Успех имеет форму `{ "data": ... }`, списки добавляют `meta` с пагинацией, датой и версией набора. Ошибки имеют форму `{ "error": { "code": "...", "message": "...", "details": [] } }`.

| Маршрут | Назначение |
|---|---|
| `GET /health` | Состояние, дата и размеры набора |
| `GET /employees` | Список сотрудников для HR; фильтры и пагинация |
| `GET /employees/{id}` | Исходный профиль, требования текущей роли и эффективные навыки |
| `GET /employees/{id}/history` | История участия |
| `GET /employees/{id}/recommendations` | Результат подключённого движка |
| `GET /events`, `GET /events/{id}` | Каталог мероприятий |
| `GET /skills`, `GET /skills/{id}` | Справочник навыков |
| `GET /role-profiles` | Требования по ролям и грейдам |
| `POST /activities/{event_id}/complete` | Завершение с защитой от повторной обработки |
| `GET /hr/analytics` | Дефициты навыков и агрегаты участия |
| `POST /datasets/validate` | Проверка файлов без изменения состояния |
| `POST /datasets/upload` | Атомарное добавление или полная замена данных |

Запрос завершения содержит `employee_id`, необязательные `record_id`, `score` и `feedback_rating`. Обязателен заголовок `Idempotency-Key`: повтор того же запроса возвращает сохранённый ответ без повторного начисления. При наличии активной записи она переходит в `completed`; дата зачисления сохраняется, новая дата завершения записывается в `completed_on`. Обязательное обучение можно завершить только по существующему назначению, без начисления игровых наград.

## Данные и состояние

Официальные файлы находятся в `data/career_quest_dataset/`: 200 сотрудников, 60 навыков, 32 профиля роли и грейда, 40 мероприятий и 2 743 записи истории. Исходные файлы сохранены без изменений; датой демо служит `meta.as_of_date`, для стартового набора это `2026-10-01`.

`employee.skills` остаётся результатом последней оценки. `get_effective_skills()` единожды учитывает завершённые после неё активности. Курс не может уменьшить уже более высокий уровень навыка. Описание неоднозначностей исходной истории и принятых трактовок находится в [DATASET_NOTES.md](docs/DATASET_NOTES.md).

С `DATABASE_URL` сотрудники, навыки, мероприятия и история сохраняются в связанных таблицах схемы `career_quest`. Завершение, рост версии данных и ответ для повторного запроса фиксируются одной транзакцией. База становится источником данных: после её заполнения исходные файлы не требуются для перезапуска. Новые данные загружаются через API импорта.

Без `DATABASE_URL` используется `.runtime/state.json` и **один worker**. Файловая запись атомарная, состояние связано с исходным датасетом по контрольной сумме. Для чистого локального демо остановите сервер и переместите этот файл в резервную копию. Для хранения только в памяти также задайте пустое значение `CAREER_QUEST_STATE_PATH`. В PostgreSQL одновременные изменения разных процессов сериализуются блокировкой в базе. Остальные настройки перечислены в `.env.example`.

## Импорт данных жюри

Отправляйте multipart-файлы с полями `employees_file`, `activity_history_file`, `events_file`, `skills_file`.

- `mode=append` по умолчанию добавляет новые профили и/или записи истории. Можно прислать один файл; ссылки проверяются по всему активному набору. Повторные ID отклоняются. Ранее импортированные данные и завершения сохраняются.
- `mode=replace` требует все четыре файла и заменяет рабочий набор целиком. Старые ответы идемпотентности и сведения о runtime-завершениях сбрасываются.

JSON сохраняет официальные оболочки с `meta`; метаданные должны совпадать. CSV разбирается настоящим CSV-парсером, включая переставленные столбцы и значения в кавычках. Проверяются типы, уровни навыков, даты, уникальность и ссылки. Невалидный импорт не меняет состояние. Лимит общего содержимого файлов по умолчанию — 10 MiB.

## Подключение рекомендаций

Движок пока не подключён: маршрут рекомендаций возвращает `503`. Backend предоставляет типизированный адаптер, изолированный снимок данных, общую проекцию навыков, таймаут и кеш по версии данных. Завершение или импорт делает прежние рекомендации устаревшими.

HR-дефициты относятся к требованиям **текущей роли и грейда**. Показатель сотрудников без следующего шага получает точную сводку через необязательный быстрый метод `provider.coverage(view)` либо показывает только уже рассчитанные рекомендации вместе с количеством ещё не оценённых сотрудников. Отсутствующие результаты не выдаются за ноль. Открытие HR-экрана не запускает массовую генерацию AI-объяснений.

## Проверка

```bash
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m pytest -q
```

Тесты проверяют официальный датасет, повреждённые JSON/CSV и ссылки, новые профили, транзакционный импорт, границы доступа, рост навыков, порядок завершений, повторные и конкурентные запросы, восстановление состояния и ошибки подключаемого движка. Основные сценарии используют небольшие синтетические наборы с произвольными ID.

Для интеграционных тестов PostgreSQL задайте `CAREER_QUEST_TEST_DATABASE_URL` отдельной тестовой базы. Тесты создают и удаляют только собственные схемы `cq_test_<uuid>`; без этой переменной они пропускаются.
